Help

How Handloom fits together and how to work with it day to day. Five minutes to read; the questions at the end cover what people usually get stuck on.

The cycle

Every piece of work goes the same way. Nothing reaches your project until a person says so.

  1. AskSay what you want, in a sentence.
  2. WorkA helper does it in its own copy.
  3. CheckThe project's checks run on the result.
  4. ReviewYou read what changed.
  5. UseYou accept it, then merge it.

The order of things

The first time, once. Steps 1 to 3 are usually done by whoever runs the hub. Get started walks through them and ticks each one off.

  1. 1Add a computerOn Computers, add the machine that will run helpers and run the one command it shows. It needs git, tmux and an agent program you are signed in to (Claude Code, Codex, OMP or Pi).
  2. 2Add a profileOn Profiles, pick one from the starter library or make your own. It says which agent program a helper uses and what it may do. Keep one that only reads, and one that writes code.
  3. 3Add a projectOn Projects, let Handloom hold it, or attach one from GitHub or another host. Then have your computer fetch its own copy.
  4. 4Add the checksOn the same page, Add checks prepares a ./check. It shows you the files first; nothing changes until you press Put on the main branch.
  5. 5Ask for something smallOn Jobs, use Just ask: a sentence, a project, Start. Watch the helper work, read the result, accept or send back.
  6. 6FinishWhen the work is what you wanted, merge it into the project. Until you do, the project itself is untouched.

The parts

Where things run. Your code is worked on at the computers, not on the hub.

ComputerA machine you connected. A small program on it (the link) starts helpers, keeps their copies of the project and runs the checks.
ProjectA code repository. Each computer keeps its own copy. Held by Handloom, or attached from elsewhere.
ProfileA recipe for a helper: which agent program, what it may touch, what it was told. Every change makes a new version.
HelperA running agent made from a profile, in a terminal on a computer. You can watch its screen from its task.
Job and taskA job is something you asked for. It is split into tasks, each done by one helper in its own copy. A plain ask is one task.
LeadA helper that plans a bigger job, hands out tasks and reviews them. Ask for one when a job has several steps.
ChecksA ./check in the project. Its answer comes from the machine, not from the helper's own claim.
InboxEverything waiting for you: results to look at, questions from helpers, work that stopped.

Every day

Pick how much planning you want

One clear changeJust ask. One helper, no lead. Fastest; good for small, well-described work.
Bigger or vagueTick Have a lead plan it, and Show me the steps first so you approve the plan before anything runs.
A written definition of doneUse the kit's tasks: write a spec with its risks, have a different helper draft failing tests (handloom job draft-tests), keep the ones you want, then seal the task.

Reading a result

What changedFiles, lines added and removed, the full diff. A changed web page opens in a safe preview.
The checkGreen means the project's own tests and rules passed. It does not mean the work is the right work: read the diff.
Your optionsUse this result, Send back with a note (after three the task stops and asks you), Try again with another profile, or Stop this task. A finished task says who accepted it.

When something stops

Look in the Inbox first. It says in words what is waiting and what the options are. A stuck helper can be watched live from its task; a computer that went quiet shows on Computers.

Tips

Start smallYour first ask should be a change you could review in two minutes.
Say what not to do"Change only the footer; leave the navigation alone" gives a smaller diff and a faster review.
Describe done, not steps"Every page shows the year in its footer" beats a list of edits.
Don't trust stated factsAsk the helper to use what is in the project, and read for anything it invented.
Test and build by different helpersThe one who writes the code should not also decide what counts as done.
Keep checks honestA stage left empty in factory.toml (for example acceptance) is skipped. Fill it in once you have tests for it.
Update the checks now and thenWhen Projects shows an update, Prepare an update brings the kit up to date, with the same look-first step.
You can always say noNothing reaches the main branch without you. A result that looks wrong costs nothing to refuse.

Add-ons

An add-on gives helpers a tool they do not have, such as saving a web page as a file. The Add-ons page lists what is installed and who may use it.

What is an add-on?

A small program that runs on one of your computers and offers helpers one or more tools. A helper asks for a tool by name, the add-on does the work on that computer, and the answer comes back to the helper. Handloom works without any.

Is it safe?

An add-on is code, so install only one you trust. It is installed on the computer by the person who runs that computer, who approves exactly what is in its folder. If a single byte changes, it stops until it is approved again. A helper can use a tool only when an owner has granted that tool to its profile, with a limit on calls per job. An add-on cannot keep a secret such as a password, because anything on a computer can be read by the helpers running there. Every call is written to the record, though what was asked and answered stays on the computer.

Why can't a confidential job use some tools?

Some tools send what they are given off the computer, for example to fetch a page or search the web. A confidential job must stay on the computer, so it is never given a tool that leaves it. The owner says whether a tool leaves the computer when granting it; the job page names a tool that was held back and what to do.

How do I install one?

On the computer that will run it, run handloom addon add FOLDER, where FOLDER is the add-on's folder. It shows what the add-on can do and asks you to approve it. Then an owner grants its tools to a profile on the Add-ons page or on the profile. Helpers started after that can use them.

Questions

Does a helper change my project directly?

No. It works in its own copy on a computer. Its result is shown to you, and only a person merges it into the project.

Where does my code live?

Held projects: in a repository on the hub. Attached projects: on your git host. In both cases each computer keeps its own copy, and helpers work there. The hub stores results, not your whole working tree.

The helper says it is done, but I don't trust it.

You shouldn't have to. Look at the check result, which the computer ran, and at the diff. Neither comes from the helper's own report.

The check failed. What now?

Open the task: it lists which stage failed and why. Send back with that reason, or try another profile. A check that says "the project's own checks are broken" is a problem in the project, not in the helper: fix that first.

A task says "blocked: a person decides".

The check reached something only a person may settle (for example a change to a protected file). Read the helper's note, decide, and either accept, send back with instructions, or change the project yourself.

Nothing happens after I press Start.

Look at the job's status line. "Starting the helper" can take a minute while the computer starts it. If the computer shows as offline on Computers, the link on it is not running. If a helper is waiting on a rate-limited model, try again with another profile.

When do I need a lead?

When the work has several parts that depend on each other, or you want a plan before work begins. For one clear change, skip it.

What is "Add checks" and do I have to?

It gives the project a standard ./check and rules about what a helper may change. You don't have to, but without it Handloom can only show the diff. It always shows you the files first and changes nothing until you confirm.

Who can do what?

Owners manage people, computers, profiles and settings. Anyone who can manage projects can add a project or its checks. Accepting work and merging it are for a person, never a helper. Viewers can look but not act.

Can I use it from the command line or an AI app?

Yes. Everything on these pages is also a handloom command. See Connect an AI app for using it from Claude or another app.

How do I undo something?

Before merging: stop the task, or just don't use it. After merging: it is an ordinary commit in your project, so revert it the way you would any other. Deleting projects, helpers or jobs from the hub is not possible yet.
