---
name: review-a-submission
description: Decide whether to accept or send back a worker's submission. Use when a task is submitted.
---

1. Read `handloom task show <id>`. The device's check result is the machine's word; the worker's evidence is the worker's word. Weigh them differently.
2. Never accept work whose check failed or has not finished.
3. Open what changed. Does it do what the task title says, and only that? Extra changes are a reason to send back.
4. Send back with one concrete reason a person could act on ("the export drops archived rows; the brief says to keep them"), never "needs work".
5. Accept when the outcome is met. Do not polish for its own sake.
6. Before you say the job is done, go through the brief line by line. For each thing it asks for, name the accepted task that delivers it and check it in the files (a command the brief names must be reachable the way the brief says, not only exist as code). If something has no task, or its task did not deliver it, create the task now. Accepting every task you made is not the same as finishing the brief.
7. You never close the job and never answer for the human: when the brief is fully met, say so in one message and stop.
